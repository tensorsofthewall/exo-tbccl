# exo-tbccl 0.4.0 validation

```{warning}
**This is not a certification.** exo-tbccl 0.4.0 is a minor release of 0.3.1 that bundles TBCCL 0.7.0 (C ABI 1, wire protocol 4) and adds opt-in Metal options. This page records the validation of the development tree and of the CI-built artifacts of release candidate 0.4.0rc1, from which 0.4.0 was promoted without a code change.
```

## What changed

`exo_tbccl/group.py`, `bridge.py` and `config.py`: the opt-in `EXO_TBCCL_PREALLOC_GATHER` destination preparation (with its failure handling), the opt-in CPU-stream borrow views, and decode-timeline diagnostics in the benchmark provider. All defaults are unchanged.

## Tests on a build against the TBCCL 0.7.0 development tree

| Check | Result |
|---|---|
| Linux adapter test suite | 308 passed, 5 skipped |
| macOS adapter test suite | 326 passed |
| Fault injection of the destination preparation (fresh and reused destinations, failing abort, release on close, abort and a failing close) | covered by 12 tests; each group fails when its code is removed |
| Loaded native library | rebuilt in an isolated directory against the 0.7.0 tree and checked to contain the new AllReduce setting |
| Qwen3-0.6B canary, two stages, both orientations, 7 configurations (MlxRing, default, step, step with wait-spin, preallocation, step with preallocation, and the previous core) | output tokens and the KV prefix identical in every configuration |

## Performance review

Interleaved fresh process pairs, five per arm, both orientations, a local Qwen3-0.6B (8-bit). The new core lowered the per-token time by 1.7% (orientation A) and 3.4% (orientation B) with the default settings. Preallocation lowered it by about 0.3 ms when the Mac receives and was neutral otherwise. No regression above the measurement noise was found. The per-arm medians are on the Metal activity-policy page. PCIe AER reporting was unavailable on the Linux host, so nothing is claimed about PCIe errors.

## Release-candidate artifacts

The CI-built wheels of 0.4.0rc1 were installed on both hosts by hand over the `tbccl` extra of `tbccl-integration-v2`, with their checksums, SBOMs and attestations verified, and the loaded `libtbccl` checked to be the 0.7.0 runtime. The wheel test suites ran on both hosts (Linux 306 and macOS 324 passed; two source-layout tests need the source tree and are deselected, as in CI).

A Qwen3-0.6B canary over the Thunderbolt link (five interleaved launches per arm, median time per output token on the two orientations) produced identical tokens and KV for every arm. The default of 0.4.0rc1 matches the published 0.3.1 within noise (9.30 and 11.12 ms against 9.41 and 11.13 ms). The opt-in Metal options changed the time per token by orientation-dependent amounts and remain opt-in.

The physical checks above used a single Linux CUDA / Apple Metal machine pair. PCIe AER reporting was unavailable on the Linux host (`pci=noaer`); no statement about PCIe errors is made.
