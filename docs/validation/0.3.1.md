# exo-tbccl 0.3.1 validation (draft)

```{warning}
**This is not a certification.** exo-tbccl 0.3.1 is a patch release of 0.3.0 that adds the benchmark provider. The runtime evidence of the previous release stands because no runtime code changed; this page records what is specific to 0.3.1. The release has not been published yet, so the release-artifact checks below are listed as not done.
```

## What changed

The benchmark provider (`benchmarks/provider`, provider protocol 1) and its documentation. The adapter, the Exo fork pins, the validated MLX versions, CPython 3.13, TBCCL C ABI 1 and wire protocol 4 are unchanged. The `tbccl` extra of the immutable `tbccl-integration-v2` fork tag still installs the 0.3.0 wheel, which has the same adapter code.

## Provider tests

The provider tests (84) pass in a framework-free interpreter and in the Exo fork environment: client metrics, stream accounting, backend and placement verification, trace hooks, `describe` and `validate` output (an activity policy without the explicit experimental tier is rejected).

## Two-host smoke (development tree)

One `MlxRing` and one `MlxTbccl` lifecycle ran through the provider between the two hosts (Mac first, Qwen3-0.6B-8bit), twice including after the preflight change: both succeeded with the same placement, recorded versions and accepted `validate` on both hosts. These are smoke checks of the launch path, not performance measurements.

- The physical benchmark smoke from the released artifacts (editable and development installs are not release qualification).
